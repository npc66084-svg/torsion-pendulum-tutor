# 设计说明

本文说明当前实现的结构和边界。历史策划案已合并到本文与[开发记录](开发记录.md)，旧版本仍在 Git 历史中。

## 1. 目标与范围

程序把一次扭摆法测转动惯量实验拆成：

```text
阶段0 器材参数 → 阶段1 标定 → 阶段2 规则刚体 → 阶段3 平行轴 → 阶段4 图表与报告
```

同一套阶段同时支持两种模式：

- **真实实验模式**：学生自己的器材参数、周期和计算结果；
- **虚拟实验模式**：阶段0 参数由程序给定且只读，阶段1～3 点击生成周期数据。

两种模式的数据按 `real` / `virtual` 命名空间隔离。切换模式不删除另一边数据，也不会混算。

阶段是阅读位置，不是硬门禁；学生可以随时切换阶段，未填项在预览和检查中提示。

## 2. 运行结构

```text
浏览器
  └─ Gradio Blocks (ui.py)
       ├─ 页面控件、阶段面板、助教浮窗
       ├─ PAGE_JS：选区询问、焦点、Esc、四边缩放
       └─ 事件绑定 ──> app.handle(action, ...)
                           ├─ 更新 session["experiment"]
                           ├─ 调用 stages / uncertainty / charts
                           ├─ 调用 tutor 的 AI 函数
                           └─ 通过 get_view_state() / render_view() 回写页面
```

- `app.py`：全局单用户 `session`、`handle()` 生成器、`get_view_state()`、`render_view()`、演示数据、启动配置。
- `ui.py`：Blocks 布局、控件、CSS、`PAGE_JS`、事件绑定。
- `experiment.py`：模式、阶段、参数版本、虚拟器材参数。
- `stages.py`：阶段1～3 的测量组、学生结果、检查、作废和问题。
- `uncertainty.py`：A/B 类不确定度、传播、有效数字、回归。
- `charts.py`：阶段2/3/4 图表，带 \(u_c\) 误差棒和拟合残差。
- `report_docx.py`：把参数、数据表、结果和图导出为 Word 报告。
- `tutor.py`：模型调用、上下文、检查解释、回答批改、报告草稿。
- `session_store.py`：会话 JSON 保存、事件追加。
- `tests/`：`test_uncertainty.py` 单元测试、`smoke_check.py` 端到端测试。
- `tasks.py`、`lab_records.py`、`torsion.py`：旧版任务/记录/周期计算，仍被旧动作和回归测试使用。

单用户限制：全局 `session` 只保留一个学习会话；Gradio 队列使用 `concurrency_limit=1`。多用户同时使用需要改成按浏览器会话隔离。

### 2.1 界面结构

- **开始页 `#landing`**：固定全屏层，深色背景 + 扭摆示意图；左侧原理速览（周期、标定、测量与平行轴公式），右侧学号登录卡和演示入口；未开始学习时显示，进入后隐藏。
- **工作台 `#app-bar` 起**：品牌条（学号、保存状态、结束会话）、模式选择、阶段滑轨、阶段面板；开始学习后显示。
- 阶段0 的器材参数合并成一张卡，按物体分组；阶段滑轨在手机上自动换行。
- 窄屏时开始页改为单列：标题 → 登录卡 → 原理速览；工作台去掉模式说明、表单改为单列。

## 3. 数据模型

### 3.1 会话

```text
session
├── student_id
├── records: [event, ...]            # 追加式事件记录
├── experiment
│   ├── mode: real | virtual
│   ├── stage: params | calibrate | shapes | parallel | summary
│   ├── real
│   │   ├── param_versions: [version, ...]
│   │   ├── active_param_id
│   │   └── stages
│   └── virtual
│       ├── param_versions: [virtual-v1]
│       ├── active_param_id
│       └── stages
└── _...                             # 下划线开头的内存字段，不写入 JSON
```

`records` 事件至少包含 `timestamp`、`task_id`、`stage`、`type`、`source`。阶段动作还会带 `mode`、`exp_stage`、`group`、`passed`、`answers` 等字段。

### 3.2 参数版本

```json
{
  "id": "pv_...",
  "label": "v1",
  "created_at": "...",
  "mode": "real",
  "settings": {
    "n_periods": 10,
    "angle_deg": 60,
    "timer_resolution_s": 0.001,
    "balance_resolution_g": 0.1,
    "caliper_resolution_mm": 0.02,
    "ruler_resolution_mm": 1.0
  },
  "objects": {
    "cylinder": {"mass": [620.0], "diameter": [99.98, 100.02, 100.00]},
    "tube": {"mass": [620.0], "outer": [], "inner": []},
    "sphere": {"mass": [], "diameter": []},
    "rod": {"mass": [], "length": []},
    "slider": {"mass": [], "diameter": []}
  },
  "note": "",
  "complete": true,
  "missing": []
}
```

真实参数版本只追加，不覆盖旧版本；「载入并采用」会写回表单并设为当前采用。虚拟版本由 `virtual_param()` 生成，只读。阶段0 允许保存不完整版本，下游计算会提示缺项。

### 3.3 阶段数据

每个模式的 `stages` 包含：

```text
calibrate
├── groups: [{id, n_periods, t0[], t1[], note, param_id, param_label, superseded}]
├── results: {I1, K, I0}
├── checks: [{at, passed, items}]
├── answers: {}
├── answers_feedback: ""
├── last_check: {stage, passed, items} | null
└── last_check_md: ""

shapes
├── groups: [{id, condition, n_periods, times[], note, param_id, param_label, superseded}]
├── results: {tube: {Iexp, Igeo, E}, sphere: ..., rod: ...}
├── checks / answers / answers_feedback / last_check / last_check_md

parallel
├── groups: [{id, condition, n_periods, times[], note, param_id, param_label, superseded}]
├── results: {I_total: {...}, slope_sym, intercept_sym, slope_asym, intercept_asym}
├── checks / answers / answers_feedback / last_check / last_check_md

summary
├── charts: false
└── text: ""
```

作废组保留在表中并标 `superseded: true`，不参与平均和回归；学生可以追加更正组。检查只保存 `items`（学生值、是否相符、提示），不保存标准答案或隐藏真值。

每组在创建时记下当时的 `param_id` 和 `param_label`，只用于显示和追溯，不参与计算：阶段1～3 仍统一按当前采用版本重算。切换版本时如果有旧组，界面会提示“会用新参数重算”，组表下方也会列出哪些组来自其他版本。

## 4. 阶段逻辑

### 阶段0

- 全部器材参数 + 测量设置。
- 每个量支持多读数；解析逗号、顿号、分号、空格、换行。
- 保存生成新版本；旧版本保留；`active_param_id` 决定阶段1～3 使用哪一版。
- 参数完整性只提示，不阻塞保存。
- 已有测量组时切换/保存版本，返回提示说明旧组会被重算；每组记录参数版本，便于追溯。

### 阶段1 标定

- 每组一对空盘/加圆柱总时间，可多读数、多组。
- 组表列出每组自己的总时间和 T₀/T₁；预览给多组平均。虚拟标定固定用同一只圆柱，I₁ 各组共用。
- 程序计算每组周期、T₀/T₁ 平均、K/I₀ 平均和不确定度。
- 学生填 \(I_1\)、\(K\)、\(I_0\)；本地检查比较学生值与原始数据的一致性。
- 学生不填不确定度和有效数字。

### 阶段2 规则刚体

- 对象：金属圆筒、实心球体、金属细杆。
- 圆筒和球体放在载物盘上，计算时减 \(I_0\)；细杆换下载物盘，不减。
- 学生填 \(I_{\text{实验}}\)、\(I_{\text{几何}}\)、\(E\)。
- 程序计算 T、I、几何值、E 及传播不确定度。

### 阶段3 平行轴

- 条件：细杆基准、5 个对称距离、4 组不对称距离。
- 学生填各条件 \(I_{\text{总}}\)，以及对称/不对称的斜率和截距。
- 图由学生填的 \(I_{\text{总}}\) 点生成；至少 3 个点才画回归线。
- 本地检查 I_total、斜率、截距是否与学生自己的点一致；不给标准斜率。

### 阶段4

- 「生成阶段2/3 图」按学生结果画柱状对比图和两张 I–距离平方图；柱状图带 \(u_c\) 误差棒，平行轴图带误差棒和残差小图。
- 「生成原始数据 CSV」导出当前模式阶段1～3 的每组总时间、周期和参数版本。
- 「导出实验报告 .docx」用 `report_docx.py` 生成 Word：参数、数据表、程序结果、两张图和附录组表；讨论与结论留空。
- 「生成实验报告草稿」把学生结果、程序算出的不确定度、检查状态、回答、参数和组摘要交给模型，按标准实验报告结构写草稿。
- 报告是草稿，不自动提交，不覆盖学生结论。

### 虚拟模式

- 阶段0 使用 `virtual_param()`，只读。
- 阶段1～3 的生成按钮调用 `measure_period()`，用固定器材参数和计时起伏生成总时间；重复点击生成多组。
- 虚拟数据只写入 `experiment.virtual.stages`，不进入真实模式。

## 5. 不确定度与有效数字

本地引擎按以下约定计算：

\[
u_A=\frac{s}{\sqrt n},\qquad
u_B=\frac{\Delta}{\sqrt 3},\qquad
u_c=\sqrt{u_A^2+u_B^2},\qquad
U=2u_c
\]

- 仪器默认：天平 0.1 g、卡尺 0.02 mm、钢尺 1 mm、计时器 0.001 s；阶段0 可改。
- 程序界面统一显示合成标准不确定度 \(u_c\)（k=1），不自动乘 2；若报告要求扩展不确定度，学生按 \(U=2u_c\) 换算。
- 周期由总时间除以 N；多组先算组内平均，再做组间平均并计入组间散布。
- \(I_1\) 由圆柱质量和直径的几何转动惯量计算。
- \(K\) 和 \(I_0\) 由 \(T_0,T_1\) 与 \(I_1\) 计算，并按传播公式合成不确定度。
- 圆筒/球体：\(I=KT^2/(4\pi^2)-I_0\)；细杆：不减 \(I_0\)。
- 平行轴：\(I_{\text{总}}=I_{\text{杆}}+m(d_1^2+d_2^2)\)；对称时 \(d_1=d_2=d\)。
- 线性回归给出斜率、截距、标准误差和 \(R^2\)。
- `format_result()` 按不确定度决定保留位数，输出“值 ± \(u_c\) 单位”。

## 6. AI 边界

AI 不计算最终实验值，也不返回标准 K、I、斜率或截距。实际流程：

1. 本地程序先计算和核对；
2. 「核对结果（本地）」立即显示；
3. 需要解释时，学生再点「请 AI 解释」，模型只解释不一致原因和核对方向；
4. 「请 AI 批改回答」逐题评价概念回答；
5. 「生成实验报告草稿」按报告结构整理学生数据。

发给模型的检查包只包含学生值、检查项、参数版本、回答和统计摘要；不包含隐藏真值、学号、密钥或记录路径。报告包包含参数、组摘要、学生结果、程序算出的不确定度和检查状态。

模型通过 OpenAI 兼容接口调用：

- `TUTOR_MODEL`、`OPENAI_API_KEY`、`OPENAI_BASE_URL`；
- 官方 DeepSeek 地址关闭 thinking；
- 检查解释/回答批改/报告草稿不使用工具调用；
- 请求超时 20 秒，不自动重试；
- 未配置密钥时，本地核对、图表和记录仍可用。

## 7. 页面与交互

- 阶段导航、模式切换、阶段面板都在同一页；未激活面板隐藏。
- 阶段0 参数表单始终可编辑；虚拟模式只读。
- 助教浮窗固定右侧，可通过四边或四角拖动调整大小；聊天区随窗口伸缩。
- Chatbot 使用独立气泡（`group_consecutive_messages=False`），连续 AI 回复不会合并。
- 选中页面文字会浮出「询问 AI」；选区文本、所在区块和前后文作为上下文，发送前可编辑。
- 图表使用 Matplotlib；上下标用数学排版，避免 Unicode 字体缺字。
- 保存失败提示「重试保存记录」。

## 8. 测试与维护

```powershell
$env:PYTHONIOENCODING = "utf-8"
.\.venv\Scripts\python.exe -m pytest tests\test_uncertainty.py -q
.\.venv\Scripts\python.exe tests\smoke_check.py
```

单元测试覆盖 A/B 类不确定度、周期换算、标定回收 \(K\)/\(I_0\)、回归、有效数字、参数版本追溯和出图；端到端测试覆盖旧版周期/核对/记录、阶段0版本、阶段1～3检查、CSV/Word 导出、图表、虚拟数据、回答批改入口、报告包、AI 模拟调用和 Gradio HTTP 启动。`.github/workflows/ci.yml` 在 GitHub 上跑同样的命令。

修改时优先保持：

- 本地计算和 AI 解释分离；
- 学生结果与隐藏真值分离；
- 真实/虚拟命名空间分离；
- 旧记录只追加/作废，不硬删除；
- 阶段不硬锁；
- 密钥、记录、备份、截图不进入 Git。
