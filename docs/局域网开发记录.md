## 2026-11-11 P1 多会话

完成规划第 12.6 节里的多会话交接。课程码、AI 限流和部署脚本见下面的 P2～P5。

### 行为

不设环境变量时，`python app.py` 仍是单机会话：

- 监听 `127.0.0.1:7860`
- 队列 `max_size=1`、`default_concurrency_limit=1`
- 界面事件仍使用 `concurrency_id="single_user"`
- 不出现课程码，也不要求浏览器 token
- 直接调用 `handle(...)` 时仍读写模块级 `session`、`params`、`DOCK`，现有冒烟测试不用改调用方式

`PILOT_MODE=1` 时：

- `APP_HOST` 默认 `127.0.0.1`，`APP_PORT` 默认 `7860`。试点示例是 `APP_HOST=0.0.0.0`、`APP_PORT=7862`
- 队列 `default_concurrency_limit=8`，事件不再绑死 `single_user`
- 每个浏览器一份 `UserContext`（会话、仪器参数、帮助浮窗）
- 浏览器用 Gradio `BrowserState` 保存签名 token。签名密钥在本机 `.pilot/session_secret`，或环境变量 `SESSION_SECRET`。密钥不进仓库、不进页面、不进日志
- 同一浏览器刷新后，用 token 找回内存里的会话；进程内注册表丢了，就按 token 里的学号和 `session_id` 从 `records/<学号>/session_*_<session_id>.json` 重建界面状态
- 同一个学号再次点「开始学习」会踢掉旧窗口。旧窗口之后的操作得到「这个学号已在另一窗口打开，本窗口已退出。」新窗口是一次新的会话文件，不会接着改旧文件
- 点「结束并新建会话」后，`active.json` 把该学号标成已结束，旧 token 不能把那次会话重新载入

同一浏览器的两个标签页共用 localStorage，因此共用一个 token，是同一个学生，不是两个学生。三个学生需要三个浏览器配置（或一个普通窗口、一个隐私窗口、另一个浏览器）。

### 做法

教学计算文件没有改：`tasks.py`、`stages.py`、`uncertainty.py`、`torsion.py`、`report_docx.py`、`charts.py`。

`app.py` 里原来几百处直接读模块级 `session`、`params`、`DOCK`。用语法树只改「函数里对这三个全局名字的读取」，改成 `_session()`、`_params()`、`_dock()`。函数内部另起的局部变量 `params`（例如当前器材版本）保持不动。赋值 `session = ...` 改成 `_set_session(...)`。

`_session()` 先看当前请求的 `contextvars` 上下文。没有上下文时返回原来的模块全局。所以冒烟测试里的 `app.session = ...` 和「已有学习会话」仍然成立。试点请求在 `handle(..., session_token=...)` 入口绑定上下文，请求结束再解开。同一个学生的请求用该上下文的锁串行；不同学生可以并行。

`handle` 的 token 是关键字参数，加在末尾。不传 token 时即使 `PILOT_MODE=1` 也走单机槽。界面只在试点模式把 token 作为额外输入传进来。

`session_store.py` 仍用临时文件加原子替换，临时文件名带随机后缀，避免并发写到同一个 `.tmp`。同一学号目录加进程内锁。每次成功保存多写一个 `records/<学号>/index.json`，只记录最新文件名和 `session_id`。会话 JSON 仍是 `schema_version = "1.2"`，不下划线开头的字段集合没有删除，也没有把内存字段写进去。

`session_registry.py` 负责 token 签名、注册表、`active.json` 和从 JSON 补上下划线内存字段。恢复时阶段、已保存的参数版本、测量组和已填结果来自会话里的 `experiment`。未保存进 JSON 的浮窗草稿、图表「已生成」标记会回到默认。

`ui.py` 的 `build_ui` 增加可选参数 `pilot=False`。单机调用方式和页面结构不变。试点模式才加入隐藏的 `BrowserState`。

`tests/test_pilot_sessions.py` 覆盖三名学生各做完阶段 1、并发写入、刷新恢复、重复登录、踢人在注册表清空后仍然有效、伪造 token、非法学号，以及两种启动参数。`.github/workflows/ci.yml` 在试点分支上会跑这组测试，并分别以 `PILOT_MODE=0` 和 `PILOT_MODE=1` 跑 `tests/smoke_check.py`；试点冒烟构建的是 `pilot=True` 界面（这一点在验收时补上，见文末）。

- `python -m pytest tests/test_pilot_sessions.py tests/test_uncertainty.py -q`：通过
- `PILOT_MODE=0 python tests/smoke_check.py`：通过，本机 Gradio 返回 HTTP 200
- `PILOT_MODE=1 python tests/smoke_check.py`：通过，本机 Gradio 返回 HTTP 200
- 另建一次试点界面：`BrowserState` 组件存在，单机界面的控件字典里没有 `session_token`

### 回滚

- 继续用单机版：在 `D:\扭摆测惯量\torsion_pendulum_tutor` 保持 `main`，或不设 `PILOT_MODE` 运行。
- 丢掉试点代码：不要合并 `lan-pilot`。需要时 `git worktree remove ..\torsion-lan-pilot`，再删除分支。`v1.0-single` 仍指向 `55ecc91`。
- 已写出的 `records/` 不要删。试点 worktree 有自己的 `records/`，没有指向单机目录里的记录。

### 已知限制

- 同一浏览器的多个标签页是同一个会话。
- 新窗口再次开始会新建会话文件，不会接管旧文件里做到一半的数据。旧文件还在。
- 刷新能恢复已写入 JSON 的阶段和测量数据。只打了字、还没点保存或添加的内容，刷新后不在。
- 图表是否已经点过「生成」不写入 JSON，刷新后要再点一次。
- 报告和 CSV 仍是临时文件。下载链接没有再做「只能由本人会话打开」的额外校验；`records/` 仍在 `blocked_paths` 里，不能靠 URL 直接下载。
- 单机模式保存时也会多一个 `index.json`。旧程序不读它。

## 2026-11-11 P2 课程码和名单

完成规划阶段 P2。只在 `PILOT_MODE=1` 且请求带了浏览器 token 时生效。不传 token，或 `PILOT_MODE=0`，仍走原来的单机入口，不查课程码。

### 行为

学生在试点页面填写学号、课程码，以及名单要求时的个人识别码。「开始学习」和「载入完整演示数据」都会先核对。

- 主机没设 `COURSE_CODE`：提示「主机还没有配置课程码。」
- 没设 `ROSTER_FILE` 或文件不在：提示「主机还没有配置名单。」
- 课程码不对、学号不在名单、识别码不对：拒绝，并且不创建会话文件。
- 名单每次登录重新读取。教师改完 `名单.csv`，下一次点击就生效，不用重启。表头可以用 `student_id,name,pin` 或 `学号,姓名,识别码`。同一学号只认第一行。`pin` 为空则不用填。
- 演示按钮固定使用学号 `000000`，不会改成输入框里的学号。`000000` 必须在名单里。
- 登录失败限速：每个学号 10 分钟内 8 次，所有学号合计 60 次。可用 `LOGIN_FAILS_PER_ID`、`LOGIN_FAILS_GLOBAL`、`LOGIN_WINDOW_SECONDS` 调整。锁定期内即使课程码正确也不能进。
- 课程码和识别码不写入会话，不放进提示文字，代码里也不打印。

不带 token 的旧调用，包括冒烟测试，不经过这道门。

### 做法

新文件 `pilot_auth.py`。`handle` 在进入 `_handle_impl` 之前调用它。界面只在 `build_ui(..., pilot=True)` 时增加两个密码框，并从事件参数里拆出来，不改变原来那些位置参数的顺序。

## 2026-11-11 P3 AI 线程池和限流

完成规划阶段 P3 的软件部分。单机路径不经过 `pilot_ai`。

### 行为

试点请求里的 `review_agent`、`answer_agent`、`summary_agent`、`draft_agent`、`ask_agent` 都进最多 6 个线程的池子（`AI_POOL_WORKERS`）。界面原本就会先交出「处理中……」，这一点没改。

- 每个学生每分钟最多 6 次（`AI_RATE_LIMIT_PER_MIN`）。超限提示「这一分钟的 AI 请求已经用完，请稍后再试。」
- 报告草稿（`summary` 和 `draft`）按北京时间自然日合计最多 3 次（`AI_DRAFT_LIMIT_PER_DAY`）。超限提示「今天的报告草稿已经用完。本地核对和已填数据仍可使用。」
- 试点调用把 HTTP 超时设为 30 秒，并让客户端再试一次（`max_retries=1`）。
- 函数自己抛出异常时，外层再调用一次。
- 外层等待超时后只提示「AI 请求超时，请稍后再试。本地核对和已填数据仍在。」不再并行开第二次。同一次上下文不能被两个线程同时进入，第二次也会和仍在运行的调用一起改会话。
- 不传这些参数时，`tutor.py` 仍是 20 秒、提问 60 秒、`max_retries=0`。

### 做法

`tutor.py` 只给五个函数加了带默认值的关键字参数。`app._ai` 在没有试点上下文时直接调用原函数。有上下文时交给 `pilot_ai.Gate`，并把当前 `contextvars` 复制进工作线程，这样工具回调仍能读到这个学生的会话。

5 个并发调用测得重叠 10 对（5 个调用两两都重叠），墙钟时间 0.403 秒。若串行，每次睡眠 0.4 秒，合计约 2 秒。

## 2026-11-11 验收与修复

用 3 个独立的无头 Edge 浏览器补做了真实页面验证，发现并修复了以下问题：

| 问题 | 处理 |
|---|---|
| 每个试点事件在生成器 `finally` 里 reset `ContextVar` 报 `was created in a different Context` | `handle` 改为每步 `next()` 前后单独 set/reset；`UserContext.lock` 改为普通 `Lock` |
| 登录失败只在服务端，开始页没有提示 | 新增 `#pilot-error`，显示课程码、名单、识别码、踢窗口和学号格式错误 |
| 结束会话也会显示红色错误框 | 错误改用独立 `pilot_error` 字段，不复用状态文字 |
| 有标定组但没有参数版本时预览抛 `AttributeError` | 预览显示「先保存一个参数版本」，图表做空值保护，并补回归测试 |
| 刷新后回到开始页 | 初始加载不碰 BrowserState；1.4 秒后自动点隐藏的「恢复会话」按钮 |
| CI 的 `PILOT_MODE=1` 冒烟没有构建试点界面 | 冒烟按 `pilot` 构建，并断言登录错误区可见 |

复验：39 个单元测试通过；单机/试点冒烟通过；3 个浏览器验证了错误课程码提示、正确登录、学生隔离、刷新恢复、重复学号踢窗口和结束会话。仍未做：教室里的真实设备、真实校园网和真实模型压测。
